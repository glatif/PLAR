How we build

Stack and ways of working

Supabase is the backbone. One managed platform in Canada covers the database, sign-in, files, background jobs and live updates.

Supabase (Canada region)

  • Postgres with row-level security, so every role sees only its own cases
  • Auth: Microsoft sign-in for staff and assessors, email links for students
  • Storage: private buckets with short-lived signed links
  • Queues and Cron for reminders, conversions and deletions
  • Realtime for notifications; pgvector for comment suggestions
  • Separate development, staging and production projects

App and hosting

  • Next.js app (already started) in the new design system
  • Deployed to our own server in Canada with a proper domain and HTTPS
  • Staging updates automatically from the main branch, and production is released on purpose
  • Interview video runs through our own media server in Canada, with Zoom as the fallback
  • Error monitoring, daily backups and a tested restore

Ways of working

  • A demo at the end of every phase, and a short written update every Friday
  • Synthetic data only until privacy approval is in place
  • AI features work with a stand-in first, behind switches that stay off until approved
  • Every feature passes the accessibility, security and audit checks before it counts as done
  • Each week's spare buffer goes into fixes, not new scope
